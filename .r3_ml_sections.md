## Independent ML assessment

The project does **not** have independent tender-level outcome labels. The
supervised target is created in live code as
`rule_score >= rule_label_threshold` (`src/thesis/anomaly/models.py:291-312`,
`src/thesis/pipeline/ml.py:370-374`), and the benchmark creates its proxy labels
from the same rule score (`src/thesis/anomaly/benchmark.py:805-806`). The feature
matrix contains direct inputs to, derivatives of, and close proxies for those
rules, as well as award-stage and full-snapshot contextual fields
(`src/thesis/domain/features.py:300-322`). Consequently:

* ROC-AUC, PR-AUC, calibration, out-of-time AUC, and `precision@K` against these
  labels measure **agreement or faithfulness to a rule-derived proxy**. They are
  not evidence of fraud detection, corruption detection, calibrated procurement
  risk, precision, recall, or a false-positive rate against real outcomes.
* The unsupervised models produce a retrospective, snapshot-relative review
  ordering. Their scores are not probabilities and cannot support a prevalence
  estimate.
* The <=2023/>=2024 split is a temporal split of the same circular proxy and a
  retrospectively constructed feature table. It does not establish forward or
  temporal generalisation.
* SHAP explains the supervised rule-proxy surrogate in terms of raw features. It
  does not establish causal importance, explain fraud, or independently validate
  a fired rule.

The current narrative generally states these boundaries correctly. For example,
`src/thesis/pipeline/ml.py:573-588` embeds the circularity warning in the generated
validation artifact, and `docs/methodology.md:252-271` restricts the supervised
metrics and temporal split to rule-proxy faithfulness. That accurate framing is a
necessary safeguard, not a substitute for validation.

The clean-room pass also found prospective artifact-integrity defects even though
the then-committed generation manually reconciled: benchmark rows were not bound
to the exact implementation source, ML did not independently re-elect champions
from released rows, a long full sweep could mutate the canonical checkpoint before
the replacement release was ready, and checkpoint JSON was too permissive. These
were real fail-closed contract defects; they were not proof that the old champion
values were numerically wrong.

Source and test remediation is now implemented. **Canonical closure is not yet
complete.** The current committed artifacts still predate the new contract:

* `data/models/benchmark/champions.json` has `schema_version: 1` and no
  `implementation_fingerprint`;
* `data/models/validation_report.json` has neither a benchmark implementation nor
  semantic fingerprint; and
* `data/models/benchmark/benchmark.release.json` does not bind
  `results.jsonl` and has no release checks.

Live source requires champion schema 2 and the implementation-bound semantic
protocol (`src/thesis/anomaly/benchmark.py:153-176`). Therefore the old benchmark,
models, SHAP, validation report, scored table, generated reports, and dashboard
data must not be cited as post-remediation evidence. A full benchmark/ML/report
rebuild and final verification are acceptance gates, not optional cleanup.

## Exact remediation summary

### Benchmark provenance and election

* `src/thesis/anomaly/benchmark.py` now declares protocol
  `2026-07-r6-implementation-bound-semantic-election` and champion schema 2.
* Nine relevant source/config/provenance files are hashed into an implementation
  manifest (`src/thesis/anomaly/benchmark.py:162-212`). Each result row binds the
  protocol, implementation fingerprint, manifest SHA, grids SHA, and model-election
  SHA (`:423-440`).
* Full mutable resume, quick smoke state, and canonical evidence are separate.
  Canonical replacement uses a flushed/fsynced temporary file and `os.replace`
  (`:444-471`).
* The semantic DQ recomputes declared-grid completeness, unique configurations,
  current protocol/implementation/data fingerprints, the composite formula,
  result-to-persisted-leaderboard equality, deterministic family/supervised winners,
  ensemble top-K, and the champion payload (`:1208-1316`).
* The full release binds canonical `results.jsonl`, leaderboard Parquet and Markdown,
  champions, and `data/dq/benchmark.release.dq.json`; the DQ payload is bound to the
  exact persisted leaderboard path, SHA-256, size, rows, columns, and dataframe
  fingerprint (`:1407-1456`).

### ML consumption and scored release

* `src/thesis/pipeline/ml.py:136-184` reads results, leaderboard, champions, and
  semantic DQ under one before/after-validated benchmark release generation.
* `src/thesis/pipeline/ml.py:187-321` recomputes the semantic election and rejects a
  missing/stale proof, old schema, quick bundle, incomplete grid, wrong winners,
  wrong top-K, stale protocol/source/data fingerprint, or invalid explainer.
* Gold and benchmark manifest SHAs are captured before the long stage and supplied
  to publication (`src/thesis/pipeline/ml.py:350-367,677-696`).
* The scored Gold DQ payload is produced from the persisted Parquet artifact through
  `SuiteResult.release_payload` (`src/thesis/pipeline/ml.py:657-672`).

### Statistical sensitivities and detector edge cases

* Three alternate election-weight scenarios and a `precision@K`-only rank comparison
  are emitted as rank sensitivity, never as outcome validation
  (`src/thesis/anomaly/benchmark.py:1052-1109`).
* Vote membership is recomputed at q=0.90, 0.95, and 0.99, reporting count, share,
  and Jaccard against the declared set; the artifact says this is not confidence
  calibration (`src/thesis/anomaly/validation.py:208-258`).
* Deployed detector families are refit on two declared feature subsets. Only
  Spearman rank correlation and top-5% set overlap are reported, with explicit
  denials of accuracy, causal importance, external validity, or temporal validity
  (`src/thesis/anomaly/validation.py:285-371`).
* PCA is treated as stochastic under automatic SVD, and HBOS assigns explicit
  epsilon tail mass outside fitted support (`src/thesis/anomaly/detectors.py:189-214,
  233-236`).

### Documentation and dashboard

* Page 6 renders the limited-repeat warning, vote-quantile membership sensitivity,
  and feature ablation with non-validation caveats
  (`streamlit_app/pages/6_Validation.py:188-253`).
* Page 7 uses a release-SHA-keyed guarded bundle read, renders election sensitivity,
  and shows data/protocol/implementation provenance
  (`streamlit_app/pages/7_Krahasimi_i_Modeleve.py:31-49,289-348`).
* README, methodology, operations, architecture, and ADR 0002 describe the new WIP
  and release contract and maintain the retrospective/proxy-only boundaries.

## Remaining evidence limitations and blockers

1. **No independent outcomes.** A qualified, blinded tender-level review or a
   proven exact-tender external outcome dataset is required. Rule-derived labels,
   aggregate supplier overlap, and synthetic labels cannot close this limitation.
2. **No completed human labels.** Human fields must remain untouched and empty
   until real reviewers complete them. Empty sampling strata are population facts,
   not cells to backfill.
3. **Retrospective feature timing.** Award facts and snapshot-wide ranks preclude a
   pre-award or true forward evaluation. A future temporal design must fit every
   imputer, rank/z-score reference, quantile, detector, and threshold using only the
   training/reference period and test against an external target.
4. **Limited repeats.** Four bootstraps and two extra stochastic seeds are useful
   smoke/repeatability diagnostics only. They do not quantify uncertainty.
5. **Author-selected objective and feature geometry.** Election weights, top-K,
   feature representation, and vote quantiles are sensitivity choices without
   outcome calibration.
6. **Snapshot-relative score scale.** Rebuilding on a different population can
   change ranks, context, normalisation, rules, and membership even for unchanged
   rows. There is no frozen production scoring contract.
7. **Canonical generation is stale.** The implementation is deliberately ahead of
   the artifacts. Until regeneration, dashboard render failures caused by provenance
   mismatch are correct fail-closed behavior.

## ML acceptance gates after integration

The ML/benchmark portion should be marked complete only after all of the following
are evidenced in the final R3 remediation report:

1. Run the full benchmark, not `--quick`, after final upstream Gold publication.
2. Show exactly 35 expected, successful, unique full configurations; no quick,
   failed, malformed, extra, duplicate, stale-protocol, or stale-implementation row.
3. Show schema-2 champions and a passed semantic DQ whose result and leaderboard
   bundle fingerprints are identical and whose leaderboard path/hash/size/shape
   binding matches the persisted file.
4. Validate that benchmark release artifacts include canonical `results.jsonl`,
   leaderboard Parquet/Markdown, champions, and the passed semantic DQ check.
5. Run ML from that release and show one consistent data, protocol, implementation,
   semantic, Gold-manifest, and benchmark-manifest chain through feature list,
   model bundle, validation report, SHAP, scored table, and ML release metadata.
6. Confirm q=0.90/0.95/0.99 vote sensitivity and both feature-ablation subsets are
   populated, while preserving all non-validation caveats.
7. Regenerate reports/dashboard outputs only after authoritative artifacts exist;
   rerun all Streamlit render and cautious-claim tests.
8. Run the complete repository test suite, Ruff formatting/check, mypy, notebook
   JSON/Python-AST checks, release validators, DQ suites, pipeline status/freshness,
   and the final stale-claim/path/number scan.
9. Report final row counts, artifact SHA-256 values, release manifest SHAs,
   generation IDs, and all four benchmark fingerprints from the regenerated
   generation. Do not reuse the hashes or champion identities from `.audit_r3_ml.md`.
