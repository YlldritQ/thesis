# R3 clean-room pipeline, lineage, release, and reproducibility audit

**Audit mode:** independent Phase 1 review only. `THESIS_REVIEW_R2.md` and
`THESIS_REVIEW_R2.1.md` were not opened, read, grepped, statted, or otherwise
consulted. No project implementation or canonical artifact was edited by this
reviewer. Test rebuilds and probes wrote only to `/tmp`; this note is the sole
project file created by this reviewer.

**Scope:** Bronze -> Silver -> Gold -> benchmark -> ML/reporting lineage; source
hashes and staged completeness; prepublication DQ; atomic/manifest-last
publication; required artifacts, hashes and fingerprints; mixed-generation
defences; freshness/invalidation; serialization; stale/orphan outputs; tests,
lint, typing, container/CI reproducibility.

## Executive verdict

The **current on-disk generation is internally coherent and reproducible in the
current environment**, but the pipeline is **not yet thesis-grade as a release
system**. I found no present P0 corruption: all three existing release manifests
validate, raw gzip and JSONL are identical after decompression, all live DQ
ERROR gates pass, benchmark/model/data fingerprints agree, fitted models rescore
exactly, and an isolated live-code rebuild reproduced all Silver and base-Gold
Parquets byte-for-byte.

That clean snapshot does not remove four structural P1 defects:

1. Bronze and Silver lack a generation commit manifest; their multi-file swaps
   can expose mixed generations after a crash or concurrent run.
2. DAG freshness does not bind source code or current configuration/protocol,
   and Silver freshness is only existence/mtime based. A code/config change can
   leave `pipeline status` green and silently skip the affected stage.
3. Release sidecars contain absolute paths and release validation insists on
   those paths. A byte-identical copied release fails validation, including the
   documented `/data` Docker-volume use case.
4. Silver producer DQ evidence is not bound to Silver outputs, and several
   published summaries/artifacts have no semantic prepublication suite.

These are genuine defects, not evidence that the current numbers are wrong.
They must be fixed before the pipeline can support strong claims of portable,
fail-closed, generation-consistent reproducibility.

## Acceptance gates for remediation

This track should not be marked resolved until all of the following pass:

1. Bronze and Silver publish validated manifest-last bundles and injected
   mid-publish failures cannot expose a readable mixed generation.
2. Stage manifests bind code/config/protocol digests; a code, config or relevant
   library change makes that stage and descendants stale.
3. Copying a complete release to a new data root validates and loads; the
   Docker `/data` smoke test loads a released dashboard table.
4. Silver producer DQ evidence and all material summary/model auxiliaries have
   manifest-bound semantic checks.
5. Failed writer bodies preserve both prior canonical bytes and prior sidecars.
6. JSON publication is strict and typed (`allow_nan=False`), with NumPy/pandas
   boundary tests.
7. Dashboard caches are generation-keyed.
8. Exact pytest, Ruff, mypy and container-health commands all pass.
9. Regenerated manifests/sidecars/artifacts retain the current row/hash/fingerprint
   evidence or explicitly document and recompute any justified change.
