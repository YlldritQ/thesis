# R3 ML / benchmark remediation handoff

## Status

Implementation and focused verification are complete. Canonical benchmark, model,
SHAP, validation, scored-table, report, and dashboard data artifacts were **not**
regenerated in this track, by instruction. The previously committed releases are
therefore intentionally stale under the new implementation-provenance contract and
must not be cited as post-remediation results.

## Root causes remediated

1. Benchmark checkpoint reuse was bound to data/settings but not to the exact source
   implementation that computes metrics and elects winners.
2. ML validated the champions JSON contract but did not independently re-elect the
   champions from the released checkpoint/leaderboard.
3. The benchmark release did not bind the canonical JSONL checkpoint or a semantic
   completeness/election proof; both quick rows and the long full sweep could mutate
   the prior released checkpoint before a replacement release was ready.
4. Checkpoint writes used permissive `default=str`, and corrupt lines could be skipped.
5. The declared composite had no model-election sensitivity; `precision@K` conflict was
   not exposed.
6. No deployed-model refit ablation quantified reliance on lower-derived versus
   outcome-related feature families, and the top-rank vote was not stress-tested at
   alternate quantiles.
7. PCA was incorrectly classified as deterministic despite `svd_solver="auto"`; HBOS
   silently clipped out-of-support values into the nearest edge bin.
8. The benchmark dashboard cache had no release digest argument and bypassed the
   guarded reader through `.__wrapped__`.
9. Long benchmark/ML stages did not prove that upstream release manifests remained the
   same generation from read through publication.

## New schema fields

`implementation_manifest_sha256`, and `model_election_sha256` (alongside the existing
protocol/settings fields). Champions schema 2 adds `implementation_fingerprint`, exact
winner `config_key` values, `composite_weights`, `model_election_sensitivity`,
`precision_at_k` for family winners, and `cv_prauc_mean` for the supervised winner.

fingerprints, canonical result and leaderboard bundle fingerprints, and the semantic
election fingerprint. `validation_report.json` adds
`benchmark_implementation_fingerprint`, `benchmark_semantic_fingerprint`,
`limited_replication_note`, `model_election_sensitivity`,
`rank_agreement_quantile_sensitivity`, and `deployed_score_feature_ablation`.
